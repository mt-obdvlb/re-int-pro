## 第一轮真正搭建的具体范围（待批准）

创建实际前后端目录、锁文件与最小 CI；React 空态/运行页框架，FastAPI health 与契约错误处理；SQLite 初始迁移、运行事件持久化；FakeLLM 与一项假探测，JSON logging 与本地 OTel span；最小安装/运行说明、`.env.example` 无密钥模板；Apifox health 用例指向本地后端并保存报告。此关先证明开发链路成立，不提前堆完四类故障与全部算法。

P1 验收建议命令在真实脚本创建后写入 README：`uv sync --frozen`、`uv run pytest`、`uv run ruff check .`、`pnpm install --frozen-lockfile`、`pnpm typecheck`、`pnpm build`。当前仅是将要提供的命令清单，仓库现在不可执行这些应用命令。CI 不使用真实 BAILIAN_API。

## 风险与收敛

| 风险/触发信号 | 处理 | 工时/资源边界 |
| --- | --- | --- |
| 本机容器内存紧张、服务频繁不健康 | 限制实验栈资源、一次一个快照；先快照后停实验栈再跑批次 | 不迁移付费云或强上 Kubernetes |
| 故障太容易被单指标识别 | 为开发集增加相似症状与缺失观测，冻结后不改测试集 | 机动 ≤8h；不以人为藏答案制造虚假改进 |
| 模型假设预测无效 | 分析候选覆盖/预测误差，收缩故障族或接受负结果 | 机动 ≤16h |
| API 调用预算异常 | 到450元停止准入，核对账单、usage、重试和地区 | 不增加500元硬限 |
| Apifox CLI 与项目维护模式不兼容 | 查官方 help/schema、客户端和实际资源；记录最小手动动作或阻塞 | 不逆向私有接口，不建同名替代项目欺骗交付 |
| 可观测性占用过多 | 事件完整保留，trace有界导出，关高体积正文 | 不删关键失败路径日志换性能 |

## 最终面试证据包

准备架构图、一次带竞争解释的真实运行、一个错误或未知案例、同预算对照与消融图、关键代码定位、费用对账和个人贡献清单。自然连接 408 的进程/线程与并发、锁/事务、网络超时与重试、图和贪心算法、缓存与一致性；数据库事务与软件测试作为工程延展，不冒充 408 所有内容。

讲述核心应能解释：为什么每轮动作依赖反馈；为什么 D/c 只是信息价值代理；为什么必须同模型同预算；为什么诊断成功不能等价于 HTTP 200；为什么可观测性和真实证据比长段模型分析更可信。现有 [逐题讲稿](topic-interview-scripts.md) 的 T1 仅供预演，P6 再按实测改写，不提前填结果。
