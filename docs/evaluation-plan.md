# 实验、预算与判定规则

本文件将 T1 的历史选题方案收敛为待实施实验；API 供应商已按用户选择改为百炼。旧候选文档中的 DeepSeek 报价不再用于本项目实施。没有实测成功率，也没有发生本轮模型消费。

## 数据与可重复性

计划创建 80 个合成但由真实实验服务产生的事故快照：连接池耗尽、任务队列积压、缓存延迟、配置错误各 16 个（共 64），正常 8 个、未知/证据缺失 8 个。20 开发、60 保留测试；四类各 4 开发/12 测试，正常与未知各 2 开发/6 测试。初版不把组合故障作为必须准确定位的任务。

按故障类型分层，按模板族和参数区间分组划分；同一基础模板的不同随机种子不能跨开发/测试集。测试集是真值/参数留出，并不宣称故障类别零样本泛化。预登记参数区间、负载种子、随机化后的不含真值 incident_id、reset/check 健康检查和捕获窗口。人工核对 10 个快照是否符合注入预期；失败的捕获不纳入数据，保留排除原因，再以同规则补齐。

故障标签、注入配置、评分规则放 evaluator 私有目录。Agent 仅获得告警、依赖图、允许查询的观测视图，不获得文件名暗示、标签、注入进程日志。数据 manifest 含内容哈希、生成代码提交、窗口与版本；冻结后不在测试集调提示、阈值和成本权重。公开发布前单独核查许可与个人信息。

## 六种配置与公平比较

| ID | 策略 | 固定项/改变项 |
| --- | --- | --- |
| fixed | 人工固定指标→日志→trace→配置 | 无自适应选择，最后用同模型结构化总结；程序可提前处理显然缺失 |
| react | 普通推理—工具—反馈 | 同工具、同观测、相同硬上限；模型选择探测，不提供 U 排序 |
| graph_greedy | 依赖图局部贪心 | 从告警服务按依赖距离与异常程度推进；受图方法启发，非 GALA 完整复现 |
| competitive_cost | 完整竞争假设 + D/(c+0.1) | [Agent 设计](agent-design.md) 中的完整机制 |
| no_cost | 去成本消融 | 候选、预测、停止规则相同，排序只用 D；并列使用固定工具字典序，避免暗含成本 |
| random_probe | 去区分度消融 | 保留候选/更新/合法工具集合，均匀随机选择未探测工具，保存种子 |

六者使用相同模型快照、提示信息权限、输出上限、工具超时和数据快照。每题各跑三次：60×6×3=1,080 次主实验。fixed 实际调用可能更少；除共享上限外再画同实际花费/工具次数区间的质量曲线，不通过给完整方法额外调用来证明优势。对使用同种组件的消融复用公共实现，保存唯一配置差异。

先用 20 开发例测试最强两个可用基线，每例一次共 40 次 pilot，确定信号是否够用。pilot 不承诺效果，目的包括候选覆盖率、schema 有效率、数据真实性与成本测量；不在 pilot 后查看测试标签挑任务。

## 指标与统计

- 主指标：四类已知单故障测试任务的 component+fault_type 完全正确率，48 个任务作为分母；所有终态纳入，failed/cancelled 记未成功，另报系统失败率。
- 全任务报告：60 个任务上 known 的正确定位、normal 的未误报、unknown 的拒答/未定位分别计数；禁止把 unknown 全判 unresolved 后宣称总体准确率超过别人。
- 有害断言：unknown/normal 上错误 located 的比例；known 上错误 located 与 unresolved 分开。证据引用是否存在由程序核验，证据是否支持结论抽样盲审，不能全交给同一 LLM 裁判。
- 机制指标：初始/最终候选覆盖率、预期观测命中率、每次探测真实排除候选数、重复探测数、有效证据数、停止时剩余竞争解释数。
- 成本：真实与 uncertain API 元、输入/输出 tokens、LLM 尝试数、探测成本单位；延迟报告 p50/p95 与超时截断比例，不只看成功样本。
- 每任务三次先求均值，再按任务进行配对 bootstrap（10,000 次，固定统计种子），给完整方法减 react/graph_greedy 的差及 95% 区间；同一任务重复不能当独立 180 个样本。按故障族分层报告，避免总体平均掩盖单类退化。

两个消融为主要机制检验，其他比较为探索性。若区间跨零，表述“当前规模证据不足”；只有成本下降而质量保持时，报告质量—成本取舍。阈值选择、重跑原因、基础设施失败、提供商错误全部保留。服务器中途升级模型则停止批次，不混合成一个结果。

## 百炼预算（2026-09-05 核查）

报价适用于北京 `qwen-plus-2025-12-01` 非思考、每次输入≤128k：输入 0.8 元/百万 tokens、输出 2 元/百万 tokens；不依赖免费额度、缓存或优惠。[百炼官方模型价格](https://help.aliyun.com/zh/model-studio/qwen-plus)

单次请求上限按 12k 输入、2k 输出：0.012×0.8 + 0.002×2 = **0.0136 元**。每运行最多 16 次尝试：**0.2176 元**，低于单运行 0.25 元准入上限。

| 项 | 上限估算（元） | 假设 |
| --- | --- | --- |
| 主实验 | 235.008 | 1,080×16×0.0136；连 fixed 也按上界计 |
| 40 次开发 pilot | 8.704 | 40×16×0.0136 |
| 集成调试与提示开发 | 60 | 单独账本，不与主实验重复隐藏 |
| 失败重跑、费率偏差、演示 | 80 | 受项目准入上限约束 |
| 合计计划包络 | **383.712** | 余量不自动成为额外实验授权 |

预算硬限 500 元，软件在 450 元停止接收新增费用，50 元保留账单对账。token 估算失准、地域不符、开启思考、模型切换均可能使公式失效，集成阶段先用至多 1 元烟测核验，不符合则先修订预算。当前只确认 BAILIAN_API 非空，未验证地域/额度/权限。全部故障服务本地运行，不依赖付费云主机。

## Go / No-Go 与负结果

到 P2：四种探测能获得真实有效的观测，10 个数据检查无标签泄漏；否则暂停 Agent 调优先修环境。到 P3：20 开发例至少 90% 能正常完成流程（located 或 unresolved），schema/权限/预算/取消检查无未处理错误；这是工程门槛，不是准确率结果。

若候选覆盖不足，先检查工具可观测性和问题定义；最多投入预留的 16 小时改善，不无限追加 prompt。若成本代理排序无效，保留消融负结果，降低创新主张为可解释诊断工程系统。到最终验收，无显著提升也可交付，只要比较公平、代码可靠、负结果可复现。不能为追求亮点删失败样本。
