# 机制补强：开发集实验约定

冻结日期：2026-09-09。基准代码：`cfa7912`（competitive-v2 / proposal-v2）。本约定在新批次调用和改进实现之前写入；新结果不得覆盖旧批次。

## 问题和范围

1. 当前封闭的四故障族是否用领域规则就能解决？建立独立的规则基线，不能将 FakeLLM 的工程检查改名为基线。
2. 只剩一个候选时，D 恒为 0，旧策略按便宜程度继续探测。选择尚缺工具通道的异常预测，能否减少无用探测？成功验证器保持不变，不因先验猜测就宣布成功。
3. 原成本下限和平滑项是否影响排序、是否真有收益？不得改大某项成本制造优势。
4. 模型遗漏候选、错误预测和探测排序分别造成多少失败？旧运行初始候选历史缺失，不能从替换后的候选倒推。

只分析冻结的 20 个开发任务；60 个测试任务不用于此次调参。原始快照、成本、真值、模型、提示、分数、两类异常证据/分差/无反驳条件均保持。将两类工具通道称为通道多样性，不称统计独立。

## 实验设计

- **完整旧策略运行**：20 个开发任务各一次，现有百炼适配器、持久化费用库和 1 元累计操作限额；保存完整候选事件。无屏蔽失败、挑例或成功后重试。模型失败也留行。
- **共享候选回放**：每任务只提取第一次 `hypotheses_updated` 的零分候选；没有记录即缺失，不用最后候选替代。每个候选矩阵供所有排序版本共享，以相同快照和验证器重放，禁止额外模型调用或候选重建。比较旧 D/c、新验证探测、去成本、固定顺序、随机顺序（种子 42）；这些是排序对照，不冒充完整 ReAct 或原 fixed Agent。
- **规则基线**：独立运行手写四条领域签名，每条要求其指标/配置及日志同时异常，其余已知签名的指标/配置正常；只使用同一 Gateway。规则按固定顺序读取，不能看任务 ID、split、真值或控制器。无 LLM、无模型生成预测；缺失、冲突及多故障保留 unresolved。它具有与 Agent 相同的观测访问权限；两者算法先验不同，明确披露。
- **成本敏感性**：固定原 costs，平滑项取 0、0.01、0.1、1；另设全部成本相同和去成本排序。比较探测序列变化、步数、按原 costs 核算的累计代理成本、成功与误定位。原始标定未保存每项 p50_ms/p50_bytes，不能倒推去下限成本；重新测量须标为新本机测量，不能当原始账单。
- **失败归因**：已知故障的初始候选覆盖；真候选对可用观测的已知预测覆盖/一致性；完全相同预测的候选对；首次反驳真候选的观测；D=0、全部反驳、支持不足等终止原因。完整运行与仅初始候选回放分开报告。

## 报告和验收

报告已知故障正确数/分母、误定位与未定位、负例误定位、平均探测数/代理成本；共享任务配对差值及任务级 bootstrap 95% 区间（10,000 次，seed 42）。新旧成功集合不同，另报共同成功任务的探测差，避免把提前失败当省成本。20 任务一次调用只是开发诊断证据，不是最终准确率或统计泛化证明。

结果保存来源哈希、初始候选哈希、快照哈希、代码/协议版本、真实 usage 费用。回放不产生新费用，不能把同一次提案费重复记成多次支出，也不能称重放耗时为在线延迟。若排序无收益、规则更好或模型预测错误，照实保留并收缩简历主张。

只有可复现结果支持改进后才更新简历。用户掌握程度仍需本人无屏幕回答，不能由自动测试代替。
