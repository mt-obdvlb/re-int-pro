# unknown导致零分歧时的补查

2026-09-09，在reliability-v4-dev开始后追加，属于开发中发现问题的探索性修正，不改写原预先约定。

首批四个连接池任务均未定位。核查首例记录发现：剩余候选分别明确预测自己的局部异常，但对其他组件给unknown，D为0。现有停止条件把“两个已知预测不相异”误当作所有候选均不可检验；实际上正常的局部观测仍能反驳某个候选。

拟增加competitive-v5补查：仅当D=0且某probe在部分活跃候选中有明确预测、在其他候选中为unknown时，按明确预测数/成本选一个可检验子集。仍然用实际不匹配才反驳，unknown不计支持或反驳。全部预测完全相同、全部unknown均不产生此分支。不得把这个分数称为统计信息增益。

两份真实初始候选分别回放“前缀停止”“完整核对”“完整核对＋补查”，新增对照不调用模型，不改成本/提示/标签。六格结果全部保存，模型的unknown覆盖和错误预测同时报告；若只多查而无收益也记录。原v4真实批次继续按已加载版本完成，最终v5按版本保留v2/v3/v4语义。

六格结果形成后，另取原开发任务顺序的首例执行一次v5真实联调，检查新分支、模型适配器、worker和费用库协作。它只证明该次运行，不加入机制成绩，不失败后挑另一例；仍受同一累计1元限额。
